# v0.5.6 UX Issues Identified

## Issue: Confusing Submenu Navigation on Attention Dashboard

### Problem
When expanding pod groups on Attention Dashboard (pressing Enter on grouped items):
- Shows nested pod list with submenu appearance
- Visual hierarchy unclear (looks like nested menus, but they're pod items)
- Navigation pattern inconsistent with rest of app

### Example
```
WARNING:
6. ▼ 🔺 467/339× DNSConfigForming    Warning events    cluster
    ├─ etcd-w-guard-wg-cp-svtk6-lqtxw (32617 events)
    ├─ kube-proxy-w-guard-wg-cp-svtk6-lqtxw (32676 events)
    ├─ kube-scheduler-w-guard-wg-cp-svtk6-lqtxw (32641 events)
    └─ and 5 more pods (press Enter for logs)
```

**Confusing because:**
- Looks like submenu but items are pods
- User expects Enter to expand further OR view diagnostics
- Actual behavior unclear

## Root Cause
- `[Enter]=logs` hint suggests entering pod logs directly
- But diagnostics view is more valuable for problem pods
- Diagnostic-first philosophy not applied to Dashboard

## Principles Violated
1. **"Show, Don't Ask"** - Not showing diagnostic value upfront
2. **Inconsistent navigation** - Different behavior vs pod list
3. **Missing context** - User doesn't know what Enter will show

## Proposed Solutions (for v0.5.7+)

### Option A: Direct to Diagnostics (Recommended)
- `[Enter]=diagnostics` from Dashboard expanded view
- Consistent with pod list behavior
- Shows maximum intelligence first

### Option B: Clearer Labeling
- Update hint: `[Enter]=view pod diagnostics`
- Make navigation expectation explicit

### Option C: Simplify Grouping
- Don't expand groups, jump directly to pod list filtered by that issue
- Single navigation pattern throughout

## Testing Recommendations
1. Test Dashboard → expand group → Enter behavior
2. Verify breadcrumb clarity
3. Test Esc navigation back to Dashboard
4. Ensure "classic" view doesn't regress

## Priority
**Medium** - UX improvement, but doesn't block functionality

Current workaround: Users can use 'c' for classic pod view with clear navigation.
