# v1.0 Killer Feature: kubectl Bundle Compatibility

**Status:** Vision Document  
**Priority:** P0 — This is the feature  
**Target:** v1.0 (12 weeks from now)

---

## The Pitch

**Users know kubectl. Bundles are opaque. Connect them.**

```bash
# Instead of learning r8s-specific commands...
r8s explore ./bundle --view=pods

# Use muscle memory from kubectl
r8s get pods ./bundle
r8s logs ./bundle nginx-pod
r8s describe ./bundle deployment app
```

| Alternative | Problem | Our Solution |
|-------------|---------|--------------|
| Custom TUI | Must learn new tool | kubectl commands |
| Web dashboard | Can't script it | CLI pipeable |

## Implementation Path

### Step 1: Native r8s Commands (v0.9.0)

```bash
# Core get commands
r8s get pods ./bundle [-n namespace]
r8s get nodes ./bundle
r8s get namespaces ./bundle
r8s get events ./bundle

# Logs  
r8s logs ./bundle <pod-name>
r8s logs ./bundle <pod-name> --tail=100
r8s logs ./bundle <pod-name> --previous

# Describe
r8s describe ./bundle pod <name>
r8s describe ./bundle node <name>
r8s describe ./bundle deployment <name>

# Top/Metrics (if available in bundle)
r8s top ./bundle nodes
r8s top ./bundle pods
```

**Output formats:** All support `-o yaml`, `-o json`, `-o wide`

---

### Step 2: kubectl Plugin (v0.9.0 or v1.0)

```bash
# Install
kubectl krew install bundle

# Use
kubectl bundle use ./support-bundle.tar.gz

# Now kubectl works
kubectl get pods
kubectl logs nginx-pod
kubectl describe deployment app
```

**How it works:**
- Plugin sets `BUNDLE_PATH` env var
- Wrapper intercepts kubectl calls
- Translates to `r8s` commands
- Returns kubectl-compatible output

---

### Step 3: Virtual API Server (v1.X — Future)

```bash
# Full API server (ambitious)
r8s server ./bundle --port=8443

# Use with kubectl
kubectl --server=https://localhost:8443 get pods
```

**Pros:** Complete kubectl compatibility  
**Cons:** Complex, maintenance burden  
**Verdict:** Only if user demand justifies it

## Technical Approach

### Data Mapping

| kubectl Resource | Bundle Source |
|------------------|---------------|
| pods | `cluster-resources/podlogs/*.logs` + pod manifests |
| nodes | `cluster-resources/nodes/*.yaml` |
| events | `cluster-resources/events/*.yaml` |
| namespaces | Derived from pod/service paths |
| logs | `cluster-resources/podlogs/*` |
| describe | Aggregate from multiple files |

### Command Implementation

```go
// cmd/get.go
var getCmd = &cobra.Command{
  Use:   "get [resource] [bundle-path]",
  Short: "Display one or many resources from bundle",
  Example: `  r8s get pods ./bundle
  r8s get nodes ./bundle -o yaml
  r8s get pods ./bundle -n cattle-system`,
  RunE: func(cmd *cobra.Command, args []string) error {
    resource := args[0]
    bundlePath := args[1]
    
    ds, err := datasource.LoadBundle(bundlePath)
    if err != nil {
      return err
    }
    
    switch resource {
    case "pods":
      pods, _ := ds.GetPods(namespace)
      output(pods, outputFormat) // json, yaml, table
    case "nodes":
      nodes, _ := ds.GetNodes()
      output(nodes, outputFormat)
    }
    return nil
  },
}
```

## Integration Points

### VS Code
```typescript
// Extension calls r8s
const pods = execSync('r8s get pods ./bundle --format=json');
const tree = JSON.parse(pods);
// Show in Kubernetes panel
```

### Claude Code / Warp Terminal
```bash
# Add bundle context to LLM
claude-code --context=$(r8s analyze ./bundle --format=json)

# Or interactive
r8s analyze ./bundle | claude
```

### CI/CD
```yaml
- name: Validate bundle
  run: |
    r8s get pods ./bundle --format=json | jq '.items | length' | grep -v 0
    r8s logs ./bundle critical-pod --tail=100 | grep -i error && exit 1
```
