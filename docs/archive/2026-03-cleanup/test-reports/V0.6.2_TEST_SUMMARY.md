### Fix 2: CodeRabbit Regression (commit 64ee48d)

**Issue:** Event reason comparison broken + healthy pods showing "NO LOGS"

**Root Cause:**
- EventReason comparison using `item.Description` instead of `item.EventReason`
- Missing state check for healthy pods

**Fix:**
- Changed comparison to use `item.EventReason` field
- Added RUNNING/COMPLETED state check for healthy pods

**Result:**
- ✅ Cluster events drill-down works correctly
- ✅ Healthy pods show "✅ POD HEALTHY - Press [l] to view logs"

### Fix 3: EventReason/EventType Population (commit 2f1c102)

**Issue:** EventReason and EventType fields were empty in attention items

**Root Cause:** Fields not populated in `computeAttentionItems()`

**Fix:** Populate both fields when creating cluster event items

**Result:**
- ✅ EventReason field contains event reason (e.g., "DNSConfigForming")
- ✅ EventType field contains event type (e.g., "Warning")
- ✅ Enables proper event matching in drill-down

### Fix 4: CRITICAL Truth Only Violation (commit 3765576)

**Issue:** Dashboard navigation showing wrong pod after sorting

**Root Cause:** ViewAttention displays in GROUPED order (critical→warning→info)
but handleEnter() was indexing into SORTED order from getDisplayedItems().

**Example of the bug:**
```text
Sort mode: Count ▼ (highest first)
displayedItems = [warn-50ct, crit-45ct, warn-40ct]

Visual display (grouped):
  CRITICAL: crit-45ct             ← position 0
  WARNING:  warn-50ct, warn-40ct  ← positions 1, 2
  
User cursor at position 1 (visually on warn-50ct)
But displayedItems[1] = crit-45ct → WRONG POD!
```

**Fix:** Replicate severity grouping in handleEnter()
1. Get `displayedItems` (respects sorting and capping)
2. Group by severity: critical, warning, info arrays
3. Build `visualOrder = critical + warning + info`
4. Index with cursor: `visualOrder[a.attentionCursor]`

**Result:**
- ✅ Cursor position matches visual display
- ✅ Works regardless of active sort mode
- ✅ Navigation always shows the pod user clicked on

### Fix 5: Cluster Event Number Keys (commit 38cd6a0)

**Issue:** Pressing 1-9 in cluster event drill-down did nothing

**Root Cause:** Event item lookup matching by Title field
("1578699× DNSConfigForming") instead of EventReason field ("DNSConfigForming")

**Fix:** Changed matcher to use `item.EventReason == a.currentView.eventReason`

**Result:**
- ✅ Number keys 1-9 work to select affected pods
- ✅ Quick navigation in cluster event drill-down functional
