## 🔍 Phase 1: Audit Findings (COMPLETE)

### Dashboard Navigation Issues

#### Issue 1: Cursor-Index Desync on Sort Changes
**Location**: `internal/tui/attention.go:63-103`

**Problem**: 
- `attentionCursor` is an integer index into the original `a.attentionItems` array
- `getDisplayedItems()` returns a **sorted copy** based on current sort mode
- When user presses 's' to cycle sort modes, the cursor index stays the same but references a different item in the sorted list
- Example: Cursor at index 5 in Count mode might reference "nginx-pod", but after switching to Name mode, index 5 references "argocd-pod"

**Impact**: Navigation feels "jumpy" - cursor appears to skip items or land on wrong entries.

**Fix Strategy**:
- Track selected item by Title (pod name) instead of raw index
- After sort, find matching Title in new sorted list and update cursor
- Call `ensureCursorVisible()` after sort mode change

#### Issue 2: Sub-Navigation State Drift
**Location**: `internal/tui/app.go:308-350`

**Problem**:
- `subCursor` can become invalid when user toggles expansion (`expandedItems`)
- No bounds validation when `subCursor >= 0` and item's `AffectedPods` list is empty

**Impact**: Potential crash or rendering issues when navigating into expanded items with edge cases.

**Fix Strategy**:
- Reset `subCursor = -1` on sort/expansion toggle
- Validate `subCursor < len(item.AffectedPods)` before rendering

#### Issue 3: Scroll Position Not Maintained
**Location**: `internal/tui/attention.go:54-62`

**Problem**:
- `ensureCursorVisible()` exists but not called after:
  - Sort mode change
  - Expansion toggle with 'm' key
  - Jump to top/bottom with 'g'/'G'

**Impact**: Cursor can be off-screen after navigation actions.

**Fix Strategy**:
- Add `a.ensureCursorVisible()` calls in handlers for 's', 'm', 'g', 'G' keys

### Log View Issues

#### Issue 4: Empty Logs - No Helpful UX
**Location**: `internal/tui/logs.go:15-59`

**Problem**:
- When `len(a.logs) == 0` after fetch, viewport shows empty content
- No guidance for user on what to do next
- FUTURE_WORK.md suggests: "No E/W — check describe/events"

**Impact**: User confusion - "Why am I seeing nothing?"

**Fix Strategy**:
```go
if len(a.logs) == 0 {
    helpText := `No logs available for this pod.

Try:
  • Press 'd' to describe pod (check status/events)
  • Pod may not have generated logs yet
  • Check pod state in previous view

[d]=describe [Esc]=back [q]=quit`
    
    return renderEmptyLogsHelp(helpText)
}
```

#### Issue 5: No Describe/Events Fallback
**Location**: `internal/tui/fetch.go`

**Problem**:
- When logs are empty, user must manually press 'd' to see describe
- Could auto-suggest or show basic pod status inline

**Impact**: Extra navigation step when pod has no logs.

**Fix Strategy**:
- On empty logs, show pod status (Ready/Status) in help message
- Encourage 'd' key to see full describe

#### Issue 6: Word-Wrap Color Highlighting
**Status**: ✅ **FIXED in v0.4.3** (verified in logs.go:102-144)

**Verification Needed**: Test with long error lines to ensure colors persist across all wrapped segments.

### Table Rendering Issues

#### Issue 7: Fixed Column Widths
**Location**: `internal/tui/table.go` (all view cases)

**Problem**:
- All tables use hardcoded column widths regardless of terminal width
- Example: Pods view uses `NAME=28, NAMESPACE=18, STATE=12, W/E=8, NODE=20` = 86 chars fixed
- On narrow terminals (80 cols), table overflows
- On wide terminals (200 cols), wasted space

**Impact**: Poor UX on non-standard terminal sizes.

**Fix Strategy**:
- Calculate `availableWidth = a.width - 8` (margins/borders)
- Allocate columns proportionally:
  ```go
  nameWidth := int(availableWidth * 0.35)   // 35% for NAME
  namespaceWidth := int(availableWidth * 0.20) // 20% for NAMESPACE
  // ... etc
  ```
- Enforce minimums: NAME >= 20, NAMESPACE >= 12

#### Issue 8: Pod Table Slow - Synchronous Log Fetches
**Location**: `internal/tui/table.go:308-340`

**Problem**:
- For EACH pod row, `GetLogs()` is called to populate W/E column
- With 50 pods, that's 50 sequential log fetches on every table render
- Causes visible lag on large namespaces

**Impact**: Table feels sluggish, especially with `--scan=500`.

**Fix Strategy**:
- Use existing `cachedPodCounts` map more effectively
- Populate cache once on initial load in background
- Only refresh cache on explicit 'r' refresh, not on every render

#### Issue 9: Truncation Inconsistencies
**Location**: `internal/tui/table.go` (various views)

**Problem**:
- Some views truncate with `...`, others just cut off
- No consistent pattern for overflow handling

**Impact**: Visual inconsistency, harder to scan.

**Fix Strategy**:
- Create helper: `truncateWithEllipsis(text, maxWidth)`
- Apply consistently across all table views

### New Hotkeys: 'e' and 'w'

#### 'e' - Jump to Worst Error Pod
**Scope**: Dashboard and Pod views

**Implementation**:
```go
case "e":
    if a.currentView.viewType == ViewAttention {
        // Find item with highest error count
        worstIdx := 0
        maxErrors := 0
        for i, item := range a.attentionItems {
            // Extract error count from item metadata
            if item.ErrorCount > maxErrors {
                maxErrors = item.ErrorCount
                worstIdx = i
            }
        }
        a.attentionCursor = worstIdx
        a.ensureCursorVisible()
        return nil
    }
```

**Files Changed**:
- `internal/tui/handlers.go` - Add 'e' key handler
- `internal/tui/attention_signals.go` - Add ErrorCount field to AttentionItem

#### 'w' - Show Warnings (Parse/Bundle Issues)
**Scope**: Global - show bundle parse warnings

**Implementation**:
```go
case "w":
    // Show modal with parse warnings
    if a.bundleMetadata.ParseWarnings > 0 {
        a.showWarningsModal = true
        return nil
    }
```

**Files Changed**:
- `internal/tui/app.go` - Add showWarningsModal state
- `internal/tui/handlers.go` - Add 'w' key handler
