```go
func renderAttentionItem(item AttentionItem) string {
    var line1 = fmt.Sprintf("%s %s %s", item.Emoji, item.Title, item.State)
    var line2 = ""
    
    if item.DiagnosticContext != nil {
        line2 = fmt.Sprintf("   → %s | Fix: %s",
            item.DiagnosticContext.RootCause,
            item.DiagnosticContext.Recommendation)
    }
    
    return line1 + "\n" + line2
}
```

SUCCESS CRITERIA:

- Recommendation actionable in ≤5 seconds
- Emoji indicators match severity
- No more than 2 lines per item (strict)

- Time to understand + act: <5 seconds

VALIDATION:
- Show dashboard to 3 developers
- Measure time from viewing item to knowing what to do
- Must average <5 seconds ("5-Second Rule")
```

## Testing Strategy

### Per-Release Testing

Each release should include:

1. **Unit Tests**
   - Test new functions in isolation
   - Mock DataSource responses
   - Verify edge cases

2. **Integration Tests**
   - Test with example bundle
   - Verify navigation flows
   - Check visual rendering

3. **Regression Tests**
   - Ensure existing features work
   - No performance degradation
   - ALL previous tests pass

### Comprehensive Testing (Post v0.6.7)

**Test Bundle**: Use production-scale bundle (100+ pods, real issues)

**Test Scenarios**:
1. Dashboard with 50+ items → scroll smoothly
2. Cluster event with 20 affected pods → drill-down works
3. Multi-container pod (5 containers) → cycling works
4. ETCD 200MB database → compaction warning shows
5. Node with MemoryPressure → utilization displayed
6. Kubelet with 100 HTTP 502 errors → aggregated display
7. OOMKilled pod → root cause + recommendation shown
8. All 7 phases → inline diagnostics consistent

**Performance Benchmarks**:
- Dashboard render: <50ms (even with 100 items)
- Log scanning: <200ms (200 lines per pod)
- Navigation: instant (<10ms perceived latency)

## Risk Mitigation

### Technical Risks

| Risk | Mitigation |
|------|------------|
| Performance degradation | Benchmark each release, cache expensive operations |
| UI complexity creep | Strict 2-line limit, remove features if needed |
| Breaking existing UX | Regression test suite, user testing |
| Backend data unavailable | Graceful fallbacks, null checks |

### Schedule Risks

| Risk | Mitigation |
|------|------------|
| Scope creep | Strict per-release scope, defer extras to v0.7 |
| Integration delays | Independent releases, no dependencies between patches |
| Testing bottlenecks | Automated test suite, CI integration |
