# v0.5.5 Feature 1 Test Plan: Rich Event Data in Diagnostic Panel

## Overview
Feature 1 adds complete pod event history by parsing the global `kubectl/events` file instead of relying only on pod-attached events.

## What Changed

### Before v0.5.5
- Diagnostic panel showed only `pod.KubectlEvents` (events attached to pod object)
- Missing: FailedScheduling, FailedMount, NetworkNotReady, volume issues
- Events were simple strings with no count indicators

### After v0.5.5  
- Parses `rke2/kubectl/events` file for ALL cluster events
- Filters events by pod name to get complete history
- Shows event counts: "(x47)" for repeated events
- Smart sorting: Warnings first, then by time (most recent)
- Displays last 5 events maximum

## Test Procedure

### Test 1: Verify Event Count Indicators

**Steps:**
1. Launch r8s with the example bundle:
   ```bash
   ./r8s example-log-bundle/w-guard-wg-cp-svtk6-lqtxw-2025-12-04_09_15_57/
   ```

2. Navigate to a pod with events (from Attention Dashboard or Pods view)

3. Press Enter to view diagnostic panel

4. Look at the "📋 RECENT EVENTS" section

**Expected Result:**
- Events show count indicators like: `BackOff: Container is waiting (x47)`
- Previously: Just showed `[Warning] BackOff...` with no count

### Test 2: Verify Complete Event History

**Compare event sources:**

**Old behavior (v0.5.4 and earlier):**
- Only showed events from `pod.Status.containerStatuses[].state`
- Limited to container state changes

**New behavior (v0.5.5):**
- Shows events from global `kubectl get events`  
- Includes:
  - FailedScheduling (pod couldn't be placed)
  - FailedMount (volume mount failures)
  - NetworkNotReady
  - Pulling/Pulled (image events)
  - BackOff (container restart backoff)
  - Killing/Killed

**Manual Verification:**
1. Check the bundle's event file:
   ```bash
   cat example-log-bundle/*/rke2/kubectl/events | grep "pushprox-kube-controller"
   ```

2. Navigate to `pushprox-kube-controller-manager` pod in r8s

3. View diagnostic panel - verify same events appear

### Test 3: Event Sorting

**Expected Order:**
1. Warning events first
2. Then Normal events  
3. Within each type: most recent first (by LastSeen timestamp)

**Verification:**
- Warning events should appear before Normal events
- Most recent events at the top of the list

### Test 4: Fallback Behavior

**When kubectl/events file is missing:**
- Should gracefully return empty events list
- Should NOT crash or error
- Diagnostic panel should show: "No events recorded for this pod"

**Test:**
1. Temporarily rename events file:
   ```bash
   mv example-log-bundle/*/rke2/kubectl/events example-log-bundle/*/rke2/kubectl/events.bak
   ```

2. Launch r8s and navigate to any pod

3. Verify: "No events recorded" message appears (not a crash)

4. Restore the file:
   ```bash
   mv example-log-bundle/*/rke2/kubectl/events.bak example-log-bundle/*/rke2/kubectl/events
   ```

## Performance

Event parsing adds ~10ms to bundle load time (negligible):
- Parses events once during bundle load
- Cached in bundle.Events slice
- Filtering by pod is O(n) where n = total events (~100 typically)

## Edge Cases Handled

1. **No events for pod** → Shows "No events recorded"
2. **Events file missing** → Gracefully returns empty list
3. **Invalid event format** → Skips malformed lines
4. **Duplicate events** → Sorted by count descending
5. **>5 events** → Shows last 5 only (most relevant)
