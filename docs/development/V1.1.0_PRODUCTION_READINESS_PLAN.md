## Code Review Process (CodeRabbit)

### Before Creating PR
1. **Self-review checklist:**
   - [ ] All tests pass (`go test ./...`)
   - [ ] Test coverage > 45% (currently 69.6%)
   - [ ] No linting errors (`golangci-lint run`)
   - [ ] CHANGELOG.md updated
   - [ ] Manual test plan completed

### PR Creation
```bash
# Push branch to origin
git push origin feature/v1.1-bundle-changes

# Create PR via GitHub CLI
gh pr create \
  --title "feat: v1.1.0 Bundle format support and bug fixes" \
  --body-file docs/development/V1.1.0_PR_DESCRIPTION.md \
  --base main
```

### CodeRabbit Review Expectations
- Review focus areas:
  1. Bundle format v1.1 implementation (versions.go, systeminfo.go changes)
  2. Path fallback logic (paths.go)
  3. Command registration fix (root.go)
  4. Test coverage (integration_v1.1_test.go)

### Handling Review Comments
1. Address each comment individually
2. Reply to each comment explaining the fix
3. Request re-review when done
4. Squash fix commits before merge
