# v0.5.5 Known Limitations

## Verbose Loading Not Visible in TUI Mode

**Issue:** The `--verbose` flag shows detailed loading output, but it's immediately cleared when the TUI starts.

**Root Cause:** Bubble Tea's `tea.WithAltScreen()` clears the terminal and takes over the display, hiding any output printed before TUI initialization.

**Current Behavior:**
```bash
./r8s ./bundle/ -v
# Prints verbose output:
# ✓ pods: 85
# ✓ logs: 172
# ... 
# Then TUI clears screen - output disappears
```

**Workaround - Redirect to File:**
```bash
./r8s ./bundle/ -v 2>loading.log &
# View in another terminal:
tail -f loading.log
```

**Workaround - Pipe to See Output:**
```bash
# This shows verbose but doesn't start TUI (because of pipe):
./r8s -v ./bundle/ 2>&1 | less
```

**Future Solutions (NOT in v0.5.5):**

**Option 1: Display in TUI After Load**
- Show bundle health in dashboard (✅ **DONE in v0.5.5**)
- Add a "Bundle Info" modal with health details
- Press 'i' to see verbose loading results

**Option 2: Pause Before TUI**
- Add `--verbose-pause` flag
- Show loading output, wait for keypress
- Then launch TUI

**Option 3: Log File**
- Always write verbose output to `~/.r8s/load.log`
- User can `tail -f` in another terminal

**Recommendation for v0.5.5:**
- Document this limitation in CHANGELOG
- Bundle health percentage IS visible in dashboard status: `📦 BUNDLE 100%`
- Verbose loading is mainly for debugging/troubleshooting
- Power users can use `2>file` redirect

## Impact

**Low** - Verbose mode is primarily for:
1. Debugging bundle load failures  
2. Seeing which files are derived vs found
3. Troubleshooting incomplete bundles

The most important information (bundle health percentage) **IS visible** in the dashboard status bar.

## v0.5.5 Delivers

✅ Bundle health tracking (stored internally)  
✅ Bundle health display in dashboard: `📦 BUNDLE 100%`  
✅ Verbose output generated (just not visible in TUI)  
⚠️  Verbose output cleared by TUI startup (known limitation)

This is a **UX polish issue**, not a functional bug. The feature works correctly - the output just isn't visible in normal TUI usage.
